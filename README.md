# Field Report

A [Claude Code](https://claude.com/claude-code) skill that turns a project (built for a hackathon, a client or a demo) into a **forward-deployed-engineer case study page**: a dark, hairline, engineering-report look, one exploded diagram of the system as the hero, and an honest ledger of what was and was not measured.

The look is deliberately locked. Consistency across several case studies is the point; only the content, the hero object, the story and the generated assets change per project. Version 0.1, experimental (see [How well does it work](#how-well-does-it-work)).

## The design system

![The whole palette: ground, ink, signal, warn](docs/img/palette.png)

Four values and hairlines. One signal colour for the signal path and the active layer; one warm colour that appears only on a miss or a gap. No gradients, shadows, glow, glass or cards. One grotesque at regular weight, mono only for figures, ids and tags. The reasons for each rule are in [`field-report-landing/references/design-world.md`](field-report-landing/references/design-world.md).

![A close-up of the hero generator output](docs/img/stack.png)

## It will not let you overclaim

Fill one config file and `scaffold_page.py` builds the whole page and a `results.json` from it, so a number on the page cannot drift from its data. If the config breaks the honesty rules, it refuses and writes nothing. This is real output:

```text
ERROR headline: absolute 'never' (say what is checked and how)
ERROR no misses: a page with no gaps is not believed. List what was not measured or what failed (or set allow_no_misses with a reason).
ERROR R1: a MEASURED figure needs a source and an as_of date
ERROR R1: bar percentage 80 is not the printed value '90%'; a bar may draw only a printed number
4 errors: nothing written
WARN  lede: quantity word with no source ('hundreds'); give it a ledger row or reword: 'Volunteers file hundreds of photos.'
```

## What is in the box

- **A workflow** Claude follows: brief, ground, direction contract, story, assets, build, honesty pass, bounded verification, an independent finish review, documentation.
- **A page generator** (`scripts/scaffold_page.py`): hero with legend, problem and response, capability frames, platform list, results ledger with misses, close; plus `DESIGN-landing.md` and `PROVENANCE.md`.
- **A hero generator** (`scripts/make_stack_svg.py`): the exploded layer stack, 3 to 6 layers, five artwork styles.
- **An asset recipe** for generating the hero orbit with Magnific (still, then clip, then graded frames), with prompts that worked and what went wrong, plus `scripts/frames_from_clip.sh`.
- **Checks:** `honesty_scan.py` (banned words, absolutes, numbers and quantity words outside data files), `asset_version_check.py` (cached rasters changed without a version bump).
- **Building blocks:** design tokens, a direction-contract template, a windowed frame-sequence loader and hook for scroll-scrubbed canvases, and style-reference frames to use when generating a hero.

## Install

Prerequisites: Claude Code; Python 3; for the optional generated hero, a Magnific account with its MCP connected, plus `ffmpeg` and `cwebp`. The skill calls the `impeccable` design skill for context and polish if you have it installed (optional, installed separately).

```bash
git clone https://github.com/abdullahabtahi/field-report-skill
ln -s "$PWD/field-report-skill/field-report-landing" ~/.claude/skills/field-report-landing
```

## Quick start

```bash
cd my-project
python3 ~/.claude/skills/field-report-landing/scripts/scaffold_page.py --example > landing.config.json
# edit landing.config.json: layers, problem, response, capabilities, ledger rows, misses
python3 ~/.claude/skills/field-report-landing/scripts/scaffold_page.py --config landing.config.json --out dist/
open dist/index.html
```

Or just ask Claude for a case-study landing page in this style. The example above lives in [`examples/northwind-ledger/`](examples/northwind-ledger/) (config and built page).

## How well does it work

Two made-up briefs, each built with and without the skill and scored by an objective grader: **20/20 vs 17/20** and **23/23 vs 18/23**.

![The same comparison on the first brief](docs/img/compare-ferryline.png)

The skill's gain is fidelity to the design system and to the honesty rules, plus a page generator that cut the second build's time; a no-skill run is not weak and can build richer interaction. An independent finish review of a with-skill page found six real issues, whose causes are fixed in the generator and rules. Full results, grader changes and limits: [`evals/RESULTS.md`](evals/RESULTS.md).

Not yet proven: automatic triggering (the trigger test returned 0% recall in its harness, so it says nothing either way), generated-hero builds, scroll sequences, interactive figures, or a real project end to end. Treat 0.1 as a strong starting point, not a finished product.
