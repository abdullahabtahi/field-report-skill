# Brief template

Ask the user for each item. Do not fill gaps with guesses; proof sources especially. Save the answers next to the direction contract.

```
PROJECT
  Name:
  One line (what it is, for whom):

MODE
  Persuade (default for a landing page). If the surface is a tool the visitor will operate, stop:
  this skill is the wrong one.

AUDIENCE
  Who reads this (hackathon judges, a technical buyer, an investor)?
  What do they already believe, and what must they believe after one scroll?

THESIS (one arguable sentence)
  "<Product> is a <form> that <claim>."

STORY BEATS (aim for 6-9; see references/story-spine.md for the default order)
  1 Hero object:
  2 Problem:
  3 Response:
  4 Capabilities (3-4, each needs real data for an interactive figure):
  5 Platform / architecture (which services, which one first):
  6 Proof:
  7 Misses to show:
  8 Close / call to action:

PROOF SOURCES (for every number you will print)
  Number | Source (doc, query, run id) | As-of | Tag (MEASURED / TESTED / NOT MEASURED / BY DESIGN / SAMPLE)
  (Mark figures that are placeholders or illustrative as SAMPLE; do not let them pass as MEASURED.)

WORDS
  Never name: (client, competitor)
  Prefer: (term A over term B)
  Avoid: (absolutes, jargon)

DATA STATEMENT
  What is real, what is synthetic, what is generated:

WORLD OVERRIDES (optional)
  Ground / ink / signal / warn values:
  Font:
  Hero object (if not a layer stack):

REFERENCES
  2-3 sites or screenshots to take grammar from (not assets):

ASSETS
  Budget for generation (credits or money), and who approves spend:
  Existing images or logos that must be used:

CLOSE
  Primary link target:
  Credit or provenance line (for example an event logo):

CONSTRAINTS
  Deploy: allowed? Perf budget? Browser support? Where the code lives:
```
